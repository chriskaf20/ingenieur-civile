### Décider

```python
taux = M_Ed / M_Rd
if taux <= 1:
    print("OK")
else:
    print("NON")
```

Le bloc indenté sous `if` ne s'exécute que si le test est vrai. On ajoute `elif` pour un cas intermédiaire. Avec un moment de 25 kN·m pour 30 kN·m résistants, le taux vaut {formatF(v0.taux, 2)} :

<IfOrganigramme taux={v0.taux} verdict={v0.verdict} />

### Répéter

```python
for a in [0, 1, 2, 2.5, 4, 5]:
    RA, RB = reactions(L, a, P)
    print(f"{a:4.1f} {RA:7.2f} {RB:7.2f}")
```

La variable `a` prend tour à tour chaque valeur de la liste ; le bloc s'exécute une fois par valeur. `range(n)` donne les entiers de 0 à n − 1.

### Définir une fonction

```python
def reactions(L, a, P):
    """Réactions (kN) d'une poutre de portée L (m) sous une charge P (kN) en x = a (m)."""
    RA = P * (L - a) / L
    RB = P * a / L
    return RA, RB
```

`def` donne un **nom** au calcul ; `L, a, P` sont ses **paramètres** ; `return` renvoie le **résultat**. La phrase entre triples guillemets, la *docstring*, dit ce que fait la fonction et dans quelles unités.

<FonctionMachine />

### L'appeler

`RA, RB = reactions(5, 2, 20)` donne RA = {grandeur(reactionsPonctuelle(5, 2, 20)[0], 2, 'kN')} et RB = {grandeur(reactionsPonctuelle(5, 2, 20)[1], 2, 'kN')}. On écrit la fonction une fois, on l'appelle autant de fois qu'il faut : dans la boucle, dans un autre programme, dans un test.

<Regle type="art">
Une fonction fait une seule chose, porte un nom clair et documente ses unités : c'est la règle de l'art qui rend un programme vérifiable.
</Regle>

<Page etape="erreurs" titre="Les erreurs fréquentes">

<Piege erreur="oublier les deux-points ou l'indentation.">
`if taux <= 1` sans `:`, ou un bloc mal décalé : erreur de syntaxe, ou pire, une ligne qui sort du bloc sans prévenir.

<Console lignes={['  File "verif.py", line 2', '    if taux <= 1', '                ^', "SyntaxError: expected ':'", '  File "verif.py", line 4', '      print("NON")', 'IndentationError: unexpected indent']} alt="Les messages de Python pour deux erreurs de syntaxe : les deux-points oubliés après le if, et une ligne mal indentée. Le message donne le fichier, le numéro de ligne et la nature de l'erreur." titre="console Python" />
</Piege>

<Piege erreur="confondre = et ==.">
`=` range une valeur, `==` compare. `if taux = 1:` est une erreur de syntaxe.
</Piege>

<Piege erreur="oublier return.">
La fonction calcule, mais ne renvoie rien : `RA, RB = reactions(…)` échoue, car la fonction renvoie `None`.
</Piege>

<Piege erreur="tester les cas dans le mauvais ordre.">
Avec `if taux <= 1.1: … elif taux <= 1:`, le second cas n'est jamais atteint. On teste du plus strict au plus large.
</Piege>

<FicheMemo titre="Fiche mémo : conditions, boucles, fonctions">

### Condition

if test: … elif test: … else: … · == compare, = affecte · du plus strict au plus large

### Boucle

for x in liste: … · range(n) : 0 à n − 1 · le bloc indenté est répété

### Fonction

def nom(paramètres): """docstring""" … return résultat · un rôle, un nom clair, les unités

### Syntaxe

« : » en fin de ligne · quatre espaces d'indentation

</FicheMemo>
